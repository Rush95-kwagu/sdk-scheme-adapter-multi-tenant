SDK scheme-adapter multi-tenant

Un processus SDK, N agents PM4ML (mcm-agent), N backends CBS. Lab openmfi — nœud 172.25.2.117.

Ce que c’est

Surcouche opt-in de mojaloop/sdk-scheme-adapter:v24.9.0. Chaque DFSP garde Vault + mcm-agent ; le SDK agrège certs et backend par requête.

Ce que ce n’est pas

Pas une PR Mojaloop. Pas le défaut production. Le flag MULTI_DFSP (préfixe backend) est un autre mécanisme officiel.

Tenants overlay actuels : cmcalavi, gto, moov-test. Le DFSP prod moov (:6000) reste hors overlay.

Cette page est servie sur la VM SDK : http://<IP-VM>/documentation (lab : http://172.25.2.117/documentation).

Fonctionnement

Le SDK officiel n’a qu’un websocket PM4ML. Un CONFIGURATION.NOTIFY déclenche un restart() global — incompatible avec N DFSPs dans le même process.

L’overlay (PM4ML_MULTI_TENANT=true) ouvre N websockets (MGMT_API_WS_URLS), range chaque conf dans DfspConfigStore sans redémarrer HTTP, et applique le slice (certs mTLS, JWS, backendEndpoint) par requête.

Agents PM4ML

L’agent (mcm-agent) n’échange pas de FSPIOP. Il enrôle le DFSP auprès du MCM Hub, stocke les PEM dans son Vault, et pousse la conf au SDK en websocket :4004 (CONFIGURATION.READ / NOTIFY).

Un agent = un DFSP (Hydra, Vault, FQDN, certs). En multi-tenant les agents restent 1:1 ; seul le SDK est partagé.

DfspConfigStore

Map mémoire dfspId → backend, endpoints Hub, JWS, PEM outbound. upsert à chaque NOTIFY. applyTo fusionne le slice dans la conf de cette requête. IDs placeholder / mojaloop ignorés. Un restart du conteneur vide le store jusqu’au prochain READ.

Compose lab : lab/docker-compose.yml (Redis + SDK). Les agents restent dans leurs stacks 1:1.

WAF

Chaque FQDN overlay : proxy_pass http://172.25.2.117:11000; (même port inbound). UI MCM : port agent (10203 pour moov-test, pas 11000).

Callbacks MCM = origine https://<DFSP_FQDN> (pas d’IP, pas de http://, pas de path /quotes).

Tests

  1. /pm4ml-tenants depuis le nœud : tous les IDs, certs > 0.
  2. Inbound : Host FQDN + Destination identique → 202.
  3. Outbound : POST http://127.0.0.1:11001/<dfspId>/transfers → COMPLETED si CBS OK.

Prérequis

Hub

  • DFSP_ID unique = Hydra client_id = MCM = ledger = Host.
  • Client Hydra client_credentials + secret.
  • DFSP MCM, zone XOF, participant central-ledger.
  • extapi.openmfi.org (mTLS).
  • DNS A : <id>.ext.openmfi.org et mcm-<id>.ext.openmfi.org → WAF 41.214.65.90.
  • Vhost nginx 443 + redirect 80. SAN *.ext.openmfi.org.

CBS

  • API joignable host:port/mojaloop (JSON, pas HTML).
  • GET /parties, POST /quoterequests, POST /transfers.
  • cbs.counterparties pour chaque FSP payer inbound.
  • Paiements initiés : http://172.25.2.117:11001/<dfspId>/transfers.

Nœud SDK

  • Docker + overlay buildable. Ports overlay 11000 / 11001 (déjà alloués).
  • Agent : Vault + mcm-agent-<id>, Status MCM 8/8, WS 4004 sur le réseau Docker seulement.
  • extra_hosts agent : hydra/mcm → WAF, extapi → 172.16.2.28.
  • Ne pas changer CoreDNS / WAF des DFSPs hors overlay (ex. moov prod).

Onboarding — nouveau DFSP

DFSP qui n’a pas encore de stack. On crée l’agent (sans SDK dédié si l’overlay est déjà la cible), puis on le branche.

  1. Hydra + MCM + participant ledger + DNS vers le WAF.
  2. Compose agent seul : Vault + mcm-agent, Status 8/8. Pas de couple inbound Hub dédié.
  3. BACKEND_ENDPOINT=host:port/mojaloop (sans espace, sans http://).
  4. CBS : comptes, aliases, counterparties.
  5. docker inspect mcm-agent-<id> → nom de réseau. L’ajouter dans lab/docker-compose.yml (external: true) et dans MGMT_API_WS_URLS : <id>@mcm-agent-<id>:4004.
  6. docker compose -f lab/docker-compose.yml up --build -d.
  7. WAF FQDN → :11000. Vhost mcm- → port UI agent.
  8. MCM callbacks https://<FQDN>.
  9. GET http://127.0.0.1:11000/pm4ml-tenants contient le nouvel ID.
Ne pas réutiliser un subnet Docker figé (erreur Pool overlaps). Vault image 1.20.4 : SKIP_SETCAP + disable_mlock + volumes UID 100. default.json doit être du JSON valide (pas un prompt shell collé).

Onboarding — DFSP existant (SDK dédié)

Cutover : le DFSP a déjà Vault + agent + SDK 1:1 (ex. moov-test sur :10200). On arrête uniquement le SDK dédié.

Ne pas arrêter l’agent, Vault, Redis du DFSP. Ne pas arrêter moov prod (:6000) pour un cutover moov-test.
  1. Exporter les réseaux Docker de tous les agents déjà sur l’overlay plus le nouveau.
  2. docker update --restart=no sdk-scheme-adapter-<id> puis docker stop.
  3. Ajouter WS URL + réseau dans lab/docker-compose.yml.
  4. docker compose -f lab/docker-compose.yml up --build -d.
  5. Vérifier que les tenants précédents sont toujours dans /pm4ml-tenants.
  6. WAF : proxy_pass de :<ancien inbound> vers :11000. MCM inchangé.
  7. CBS outbound : http://172.25.2.117:11001/<dfspId>/….

Outage Hub = fenêtre stop SDK dédié → reload WAF.

Retour arrière

WAF vers l’ancien inbound, retirer l’entrée MGMT_API_WS_URLS, docker start sdk-scheme-adapter-<id>.

Sécurité

Isolation overlay (après durcissement) : tenant inbound = Host ; mismatch Destination → 400 ; outbound sans préfixe → 404 ; /pm4ml-tenants masqué derrière le WAF ; metrics bind localhost.
